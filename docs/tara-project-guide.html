03The problem and the wedge

Compliance errors often begin with a small source change and end with stale downstream work.

A calculation can be perfectly consistent and still be wrong because it uses yesterday's rule. A generic chatbot may sound convincing but cannot prove which source version it relied on. A hard-coded rules engine is safer, but every source change becomes a code change. TARA's wedge is narrower: regulatory change-to-action with evidence.

Pain

Change is disconnected from work

Teams monitor sources, interpret obligations, schedule tasks, and collect proof in separate systems.

Buyer

Advisers and compliance teams

The first commercial user is the professional who must explain and evidence a decision—not an unsupported consumer self-filing flow.

Outcome

Faster, more defensible review

A reviewer receives the source, the rule version, the facts relied on, the action, and the proof check in one trace.

05The nine agents

Names make the demo memorable; narrow contracts make the system testable.

Open band

computed from sources; reusable across customers
SURVEY

What changed?

Hashes and structurally diffs source versions.

LEGEND

What duties exist?

Maps provisions to atomic, citable obligations.

ALMANAC

Which version is current?

Versions the obligation graph and records supersession.

Tenant band

computed from synthetic or customer-controlled facts
COMPASS

Is the pack relevant?

Evaluates scoping questions and refuses to guess.

PLOT

Which duties actually trigger?

Checks dates, thresholds, events, instruments, and prior closure.

COURSE

What happens next?

Creates dependency-ordered work with before/on/after date semantics.

ANCHOR

Is the evidence good enough?

Validates type, required fields, rate, arithmetic, and timing.

MERIDIAN

What changes across borders?

Runs every standalone pack and eligible corridor, then merges results.

ATLAS

Can we prove the path?

Records every decision in a linked hash chain.

06What makes it safer than a fluent answer

The latest hardening pass moved important safety claims from documentation into code and tests.

PASS · Effective dates

2025 selects 41%; events on or after 1 January 2026 select 38%.

PASS · Obligation predicates

A pack may be in scope while a specific duty is not. PLOT checks that difference.

PASS · Fail closed

A missing threshold or event becomes indeterminate and creates no automated action.

PASS · Directional dates

Rules declare whether a deadline is before, on, or after an event.

PASS · Exact evidence

Superseded rates and inexact calculations are returned, not silently accepted.

PASS · Audit integrity

verify_chain() recomputes and validates the entire ATLAS chain.

Technical details — obligation predicate DSL

ObligationSpec.applies_when carries deterministic field comparisons such as equals, in, gt, and lte. PLOT evaluates these only after COMPASS confirms the pack. Missing facts return indeterminate; false comparisons return not_applicable. COURSE opens actions only for partial or absent.

08Technical architecture

The simple explanation stays true when the implementation is opened.

domains/ # cited rules, scope, triggers, evidence contracts data/sources/ # controlled v1/v2 source snapshots tara/agents/ # one narrow module per agent tara/core/ # dates, diffs, pack and interaction loaders tara/pipeline.py # enforces agent order tara/mcp_server/ # ten discoverable tools tara/atlas/ # append-only hash-linked ledger demo/ # FastAPI adapter + accessible browser UI + replay tests/ # unit, integration, safety, and end-to-end tests tools/build_evaluation_card.py# executable public acceptance report public-release-manifest.txt # allowlist for a clean-history public release
Domain pack shape

A standalone pack declares sources, obligations, pack-level scoping questions, date triggers, and evidence rules. An obligation can additionally declare effective_from, effective_to, and applies_when. Corridor packs are synthesized from compact entries in domains/interactions.yaml.

Deterministic versus model-driven

Dates, threshold comparisons, effective-date selection, diffs, arithmetic, action ordering, and evidence checks are deterministic Python. An optional LLM orchestrator can decide which MCP tool to call and phrase results, but it does not own the decisive calculations.

11What TARA does not claim

A strong competition entry is specific about its evidence boundary.

Prototype boundary

TARA is not legal, tax, immigration, or filing advice. The demo uses synthetic people and controlled source snapshots. A qualified professional must review real-world actions and every domain pack before production use.

Clean public release

The private repository remains the working history. tools/build_public_release.py copies only paths in public-release-manifest.txt into a separate directory, rejects secrets and internal files, and initializes no Git history. After final review, create a new public repository and make one release commit from that directory. The private commits and messages are never transferred.

Likely judge questions
  • Where is the AI? In optional tool orchestration and explanation; decisive compliance calculations remain deterministic.
  • Why MCP? One discoverable interface lets multiple clients use the same guarded pipeline.
  • How do you prevent hallucination? Cited source snapshots, explicit pack rules, fail-closed missing facts, deterministic calculations, and an audit chain.
  • What is validated? The Maeve change-to-action loop and 112 automated tests. Independent domain sign-off remains pending.
  • How does it scale? Add a reviewed data pack; the agents and orchestration remain unchanged.
